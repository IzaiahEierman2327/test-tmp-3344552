# v0.4.0 development milestones

This plan continues the v0.3.0 Electron + JupyterLab architecture rather than replacing it. The main goals are to harden privileged boundaries, improve failure recovery, and make continued development easier without freezing the Python ecosystem unnecessarily.

## Python/runtime policy

- Keep the Workbench runtime on the **CPython 3.13 series** for v0.4.x.
- Within Python 3.13, prefer the latest stable supported patch release available from the existing `python-build-standalone` runtime source.
- Do not select Python alpha, beta or release-candidate builds.
- Python libraries should generally use the highest stable versions that remain compatible with the supported Python 3.13 runtime and the Workbench/Jupyter integration.
- Do **not** convert the Python runtime into a fully exact-pinned dependency snapshot merely for reproducibility. Runtime isolation, CI verification and compatibility tests remain the release gate.
- A future Python minor-series change (for example 3.13 → 3.14) is a separate compatibility decision and must not happen silently as part of routine dependency refreshes.

## M0 — Security and failure-boundary hardening

Completed on the v0.4 development line:

- Managed package specifications reject pip option injection and explicitly terminate pip option parsing before the user requirement.
- Privileged local BrowserWindows cannot navigate to remote content while keeping Workbench preload capabilities.
- `tools:*` IPC calls are accepted only from the active Tools window.
- Tools renderer has a restrictive Content Security Policy and cannot make provider/network calls directly.
- OpenAI-compatible AI requests have a bounded default timeout instead of waiting forever for a stalled endpoint.
- Project Euler login state survives normal application restarts even when the site uses session cookies: only `projecteuler.net` session cookies are mirrored into an encrypted `safeStorage` snapshot and restored before the first left-pane navigation.
- Chromium continues to own ordinary persistent cookies and DOM storage in the existing persistent partition; the Workbench does not duplicate them.
- Explicit logout removes the encrypted session snapshot instead of reviving stale authentication on the next launch.

Tests: package-spec regression cases, AI timeout regression, encrypted session-cookie persistence/logout cases, existing unit suite, real Jupyter smoke test.

## M1 — Managed package operation recovery

- Bound `pip list` and `pip install` subprocess lifetimes so a broken package index, stalled connection or child process cannot leave the Tools workflow pending forever.
- Keep installs on the bundled Python and persistent `python-packages/` layer.
- Preserve current upgrade behavior: a bare package specification may resolve to the newest stable compatible package available to pip.
- Do not modify the bundled base runtime while servicing user package installs.

Tests: child-process timeout regression plus existing package path-safety tests.

## M2 — JavaScript build repeatability

- Add and maintain an npm lockfile for Electron/build tooling.
- Use `npm ci` in CI/release jobs once the lockfile is present.
- This lockfile applies to the desktop build toolchain only and does not change the Python 3.13/latest-stable-compatible policy above.

## M3 — CI and release discipline

- Keep `develop` as the integration branch and `main` as the stable/release branch.
- Require unit and Jupyter smoke CI before development PRs enter `develop`.
- Before a v0.4.0 release, run the existing packaged-runtime, portable-layout and three-asset release verification on the release candidate.
- Preserve the existing Windows x64 installer + portable ZIP and Linux x64 portable tarball unless a platform milestone explicitly changes the distribution matrix.

## M4 — Product development

After the hardening baseline is merged, continue feature work on top of the existing WorkbenchService/JupyterManager boundaries. New features should preserve:

- explicit user control over saved solutions, snippets and AI source selection;
- local-first workspace storage;
- save-before-navigation/exit guarantees;
- isolation between Project Euler content, Jupyter content and privileged Electron APIs;
- no automatic answer submission to Project Euler.
