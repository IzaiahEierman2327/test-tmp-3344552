# Project Euler Workbench v0.4.0

v0.4.0 is a hardening and reliability release built on the v0.3.0 Electron + JupyterLab architecture.

## Highlights

- Project Euler login state now survives application restarts reliably. Workbench mirrors only `projecteuler.net` session cookies into an Electron `safeStorage` encrypted snapshot, restores them before the first left-pane navigation, and removes the snapshot after explicit logout. Chromium continues to own ordinary persistent cookies and DOM storage.
- Privileged local BrowserWindows are prevented from navigating to remote content while retaining Workbench preload privileges. `tools:*` IPC accepts calls only from the active Tools window, and the Tools renderer uses a restrictive Content Security Policy.
- OpenAI-compatible AI requests have a bounded default timeout.
- Managed `pip list` and `pip install` operations have bounded lifetimes. Package specifications are validated before pip is invoked, and user installs remain confined to the persistent Workbench `python-packages/` layer.
- The Electron/build toolchain now has a committed `package-lock.json`, and CI/release builds use `npm ci`.

## Python/runtime policy

v0.4.x remains on the **CPython 3.13 series**. Within 3.13, builds prefer the latest stable supported patch release and the highest stable compatible Python library versions. Python prereleases are not selected. A future move to a new Python minor series is a separate compatibility decision.

## Distribution

- Windows x64 NSIS installer: `euler-workbench-0.4.0-win-x64-setup.exe`
- Windows x64 portable ZIP: `euler-workbench-0.4.0-win-x64.zip`
- Linux x64 portable tarball: `euler-workbench-0.4.0-linux-x64.tar.gz`
- macOS is not built.

Every package includes its own Python/Jupyter runtime; the target machine does not need Python, Conda, Jupyter or Node.js installed.

## Upgrading from v0.3.0

Installed Windows users should close Workbench and run the v0.4.0 installer normally. Notebooks, application data, AI settings and managed Python packages remain outside replaceable installation files.

Portable users should close Workbench and replace the program files while **preserving the existing `data/` directory**. Release archives intentionally contain no `data/` directory.

## Behavior intentionally unchanged

- `solution.ipynb` remains the editable working notebook.
- Saved solutions and snippets require explicit user action.
- Navigation, problem switching and application exit save first.
- Jupyter remains loopback-only and isolated from host Python environments.
- AI receives only explicitly selected user notebook/solution content; Project Euler pages are not scraped for AI.
- `submit(value)` may fill the Project Euler answer field but never clicks the site's submit control.
